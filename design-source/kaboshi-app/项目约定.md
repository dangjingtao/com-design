## 2. Penpot 与 Token

- 目标文件：「卡博士」（team-id `81f57451-85cc-819d-8008-7097b210c59a`，file-id `3be9e5e1-190f-8090-8008-74d44422f05d`，当前只有空 `Page 1`）
- 组件/Token 来源：共享库 **`com-design-v1`**（file-id `3be9e5e1-190f-8090-8008-736cfb2f9bcd`，74 颜色 / 9 字体 / 81 组件，含 Light/Dark 双主题）
- **Token 使用原则（重要）：直接引用共享库，不要把值抄出来硬编码。**
  - 颜色：通过共享库的颜色 token 应用（`applyToken` / 选择库里的颜色样式），不在元素上写死 hex。
  - 字体：使用库里的 typography 样式（Display/Title/Heading/Body/Label/Caption 等），不手动设字号字重。
  - 组件：用库组件实例（`component.instance()`），不自己重画按钮/卡片/输入框等已有组件。
  - 不在本文件或台账里另存一份 token 数值副本，避免和库脱节；库更新时能同步。
- 开工前必须确认：MCP 已 Connect here 到「卡博士」文件，且在该文件里能真正读到 `com-design-v1` 的组件和颜色（若读不到，先在 Penpot 素材面板确认库已启用并同步，接受库更新）。

具体逐屏清单与状态见 `工作台账.md`。

## 4. 工作范围与顺序

- 无登录页（用户确认，不需要新建）。
- 工作顺序：按原型左侧页面树**从上到下**依次做。
- 每个线程负责一段（5-8 屏或一个完整分组），做完更新台账后再开下一个线程继续往下。
- 「暂时不做」的分组（健康管理、数字空间）先跳过，除非用户另行通知。
- 卡博士商城是 H5 嵌入页，按原生外壳 + H5 占位处理，具体待确认。

## 5. 素材图约定

- 处理方式：由设计线程自行替换成风格统一、品质靠谱的图，做完逐屏交用户审核，不合适再换。
- 替换范围：商品图、插画、图标、3D 渲染小图等所有低质感素材。
- 风格：结合品牌主色（primary `#5B5EF7`、accent `#16BFD3`）和洗护/会员打卡调性确定；保持全站统一。
- 已替换清单：在台账对应页面备注。

## 5.1 交互与设备框约定

- 交互：**尽量以原型（Mockplus）里已有的跳转和触发为准**，不自行发明流程。原型里能点哪里、跳到哪、弹窗怎么开关，照搬到 Penpot。原型没有的不补。
- 实现方式：用 Penpot 的 `addInteraction`，点击跳转画板、打开/关闭浮层（Overlay）、返回上一屏；按钮状态用变体（Variant）做 default/pressed/disabled。
- 边界：不做真实数据、表单输入、复杂动效编排。
- 手机框：内容画在干净的 390×844 画板里（开发标注用），手机外壳/状态栏/Home 指示条单独放在「演示」类画板，把内容嵌入手机框用于演示截图，**不污染开发标注画板**。

- 可复用组件全部来自共享库 `com-design-v1`（TopAppBar、Card、ListItem、Dialog、BottomSheet、Button、Checkbox、Avatar、Badge、Tabs、Search、Stepper 等）。

## 7. 已拍板的决策

- 用 Penpot 做正式交付，不用 HTML 交付
- 每屏走视觉闭环：写代码 → 导出 PNG → 对照原型核查 → 改
- 工作顺序按页面树从上到下
- 素材图由设计线程自行替换，逐屏审核
- 跨线程靠文件交接（本文件 + 工作方法 + 台账），每线程一批（5-8 屏或一个模块）
- 大屏画布：所有屏铺在同一个页面/大画布上，按模块分区，画板命名规范
- 交互以原型为准，不自己发明
- 手机壳只放演示画板，不污染标注
- Token 直接引用共享库，不抄值

## 8. 踩过的坑 / 开发反馈

- Tabs 文字在嵌套 flex 下被推到小数像素坐标会出现重影/色散，需用绝对定位锁整数坐标。
- 图标、多列布局必须导出图核对，不能只看代码逻辑。
- MCP 的 Connect here 是跟随当前打开文件的；切到工作台/其他文件会断开，读库会报 "No Penpot instance connected"，需在目标文件重新连接。
- 新建的「卡博士」文件里已连接的共享库可能需要在素材面板手动启用/接受更新，MCP 才能读到组件（曾出现连接但资产数为 0 的情况）。
