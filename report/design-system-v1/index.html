01 · Visual Language

现代、清晰、轻快，但不靠“装饰感”证明自己年轻。

目标气质：Modern / Clear / Light / Efficient。年轻感来自 Electric Indigo、信息节奏和状态表达，而不是渐变 Hero、重阴影或满屏软圆角卡片。

V1 的核心视觉判断很简单：先让信息层级成立，再决定哪里需要颜色、边界或浮起。

  • 不做政务 / 教务系统式的沉重蓝灰
  • 不做厚重企业 SaaS 模板感
  • 不做电竞霓虹与赛博朋克
  • 不做软萌、奶油化、幼稚卡通
  • 不把 Card + Shadow 当默认页面结构
  • 不让某个业务主题反向污染公司 Core

03 · Principles → Rules

原则不是海报句子，要能直接改变页面怎么画。

这几条原则决定了 V1 为什么没有做成“圆角 Card 大全”，也决定设计师在遇到新页面时先拿什么解决问题。

Compact-first

默认提高信息效率：40px 控件、48px 大控件/行基线、12px 水平 padding。但 Typography role、状态语义和可访问性不随密度缩小。

结果：视觉可以紧凑，iOS 44pt / Android 48dp 的交互区域仍独立满足。

Flat-first

常规信息层级优先 Typography → Spacing / Group → Divider / Border → Surface → Color。Shadow 不做常规分组手段。

结果：只有 Menu / Dialog / Sheet 等真实浮层才获得 elevation。

Section-before-Card

Section 是默认内容分组。Card 只在内容确实需要独立容器边界时出现，Card inside Card 默认禁止。

结果：高密度页面靠结构和节奏成立，而不是把每块信息装进一个白盒。

Semantic role first

组件引用 `action.primary / text.primary / border.focused` 等 Semantic role，不直接吃 Primitive。业务状态名称也先映射语义，再选表达。

结果：Light / Dark 可以换映射，组件行为和角色不必复制一份。

Core stays small

不是所有 UI 名词都必须进入 V1。新组件需要基础性或稳定跨产品复用，并具备 role / anatomy / states / accessibility / constraints。

结果：“另一个页面也想这么画”不是升级为 Core 的理由。

04 · System Model

四层模型负责“是什么”，四个正交轴负责“在什么环境下解析”。

V1 不生成 Dark-Compact-iOS-Reduced 这种组合 Token。组件声明自己需要的语义，各 Axis 独立解析自己的责任。

01Primitive

原始设计值：色值、字号、间距、尺寸、Shadow。没有业务含义。

02Semantic

稳定角色：text.primary、surface.default、action.primary、status.warningText。

03Component

Role、Anatomy、State、Geometry、Accessibility、Constraints。

04Pattern

用 Core 组合可复用交互逻辑，不反向修改 Core。

Axis 01Theme

Light / Dark。Dark 是 Semantic overlay，不是第二套手工组件。

Axis 02Density

Compact / Comfortable。只改变几何和节奏，不改变角色和语义。

Axis 03Platform

iOS / Android。处理 touch target、safe area、系统 dismissal 等真实差异。

Axis 04Motion

Standard / Reduced。动效解释关系，不作为装饰，也不是唯一状态信号。

Resolution Foundation → Theme → Density → Platform → Motion → Component → Pattern → Product Extension

05 · Design Patterns

真正决定体验一致性的，是组件之间怎么组织。

Component Gallery 只能证明组件单独能画。Pattern 要证明在表单、导航、搜索、反馈和流程里，角色边界不会互相冒充。

Form

Field Family 固定 Label → Control → Helper / Error。字段错误优先留在字段上下文。

Outlined / Flat · one field language

Information

Leading / Content / Trailing 建立列表节奏；超过三层信息优先重构，不继续缩字。

Section before Card

Navigation

Bottom Nav、Tabs、Segmented、Top App Bar 各有独立角色，视觉差异服务于 IA 差异。

Brand owns global active identity

Search

Search 是 query interaction，不是普通 Input 的别名；No Results 也不是全产品 Empty State。

query / clear / loading remain coherent

Feedback

反馈强度按注意力成本逐级提升。能在原位置解释的问题，不用更强打断。

local → inline → banner → transient → modal

Overlay

同一时间只允许一个 blocking modal。Menu 先关闭，再打开 Dialog / Sheet。

blocking stack depth = 1

Loading / Empty

Spinner、Skeleton、Empty、No Results、Recoverable Error 各有不同前提，不互相当皮肤。

preserve usable content on refresh

Progress

Determinate Progress、Stepper、Timeline 分别回答剩余量、任务步骤和事件历史。

truthful progress only

Status

Status 是组合语法，不是彩色胶囊本身。业务名称映射到已有语义。

color-only status forbidden

07 · V1 Scope

33 个组件不是 KPI；没有进入 V1 的东西同样重要。

V1 的目标是覆盖稳定、高复用的移动端基础能力，而不是让所有 UI 名词都拥有一个 Core Component。

Actions & Forms8

Button · Icon Button · Input · Textarea · Select · Checkbox · Radio · Switch

Navigation & Information11

List Item · Tabs · Segmented Control · Top App Bar · Bottom Navigation · Section · Divider · Card · Tag · Badge · Avatar

Feedback / Overlay / Progress11

Toast · Snackbar · Alert · Dialog · Bottom Sheet · Loading Indicator · Skeleton · Empty State · Progress Indicator · Stepper · Timeline

Search / Menu3

Search Field · Menu · Menu Item

Core Patterns2

Status Composition · Search Experience

Product / Domain Extensionboundary

业务状态、行业流程、排名/等级、主题插图和产品专有 IA 在消费 Core 后组合，不反写公司 Foundation。

V1 intentionally omits：Carousel、FAB、Data Table、Rich Text Editor、Navigation Rail 等。只有出现真实跨产品稳定需求，并且不能由现有 Core + Pattern 清晰组合解决时，才评估进入 Core。

08 · Release Candidate

这里必须保留“不完美”，否则这就不是 Design Review。

当前作者自检已完成，但 Stable 明确要求剩余验证和独立二审。下面区分 Stable blocker、历史债和适合后续版本处理的范围。

Stable 前必须关闭

  • 独立 reviewer 抽样真实 iOS / Android typography 与 controls
  • 独立验证 Manifest 引用文件、reference 与 33 + 2 count
  • PenPot Formal Spec 更新到 V1 Manifest
  • PenPot Light / Dark specimen 验证
  • PenPot Compact / Comfortable specimen 验证
  • Reusable Component Asset 与规范视觉分开验收
  • 导出 .penpot 通过 overflow / hideInViewer / stale ref / duplicate / reusable metadata 审计
  • 完成真正的独立 Review；作者自审不能把 RC 改成 Stable
Historical debt

semantic.light 逻辑命名空间

早期 Contract 使用 `semantic.light` 作为逻辑 namespace。V1 为避免发布前无收益迁移，Dark 通过 overlay 替换同一路径再解析组件。这是明确兼容契约，不代表 Dark 是二等公民。

Not fully validated

真机、动态字体、Adaptive

当前仍未覆盖所有 iOS / Android 实现环境、任意系统字体倍率，以及平板 / 折叠屏 / 宽屏 Adaptive。V1 文档给出基线，但这些不应被 HTML specimen 假装已经验证。

Later versions

让真实需求拉动扩张

未来组件、Pointer / Adaptive 扩展、业务 Pattern 与命名空间清理应在收益明确后进入后续版本，而不是为了让 1.0 看起来“完整”提前膨胀。

09 · Review Decision

放行的标准，不是“这个 HTML 看着不错”。

语言是否统一？Form、List、Settings、Feedback、Overlay、Progress 放在一起，是否仍像同一个系统。
Compact 是否真的高效？紧凑有没有伤害可读性、触控和层级，还是只压掉了多余几何。
Flat 是否足够有层级？没有大量 Card / Shadow 后，页面是否仍然清楚而不是“太素”。
颜色职责是否可执行？Brand / Accent / Status 的边界是否足以阻止产品设计各自发挥。
模式边界是否清楚？Tabs / Segmented / Bottom Nav、Toast / Alert / Dialog、Progress / Stepper / Timeline 会不会被互相替代。
系统模型是否能实现？Theme / Density / Platform / Motion 四轴是否足够独立，避免复制组件和组合 Token 爆炸。
Core 是否克制？当前 33 + 2 是否覆盖基础能力，同时给 Product / Domain Extension 留出正确空间。
RC blocker 是否只是验证债？如果独立二审发现的是设计语言矛盾，而不只是资产同步/实现验证，应回到 RC 修规则，而不是硬推 Stable。
