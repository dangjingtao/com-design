01

设计原则

先统一判断方式，再统一组件外观。

清晰 Clear

先建立任务与信息层级，再考虑装饰。状态、解释、动作与下一步必须能被用户直接理解。

结果：先排序内容与动作，再决定颜色、容器和强调。

轻快 Light

高信息密度不等于沉重。Brand 色是稀缺的层级资源，不是所有可点击区域的默认填充。

结果：Secondary / Info 优先 Neutral Surface；普通边界与占位文本保持安静。

高效 Efficient

默认 Compact，但视觉尺寸与触摸命中区域分离；复杂流程始终突出当前最强下一步，而不是平铺所有可能动作。

结果：通常一个 Primary；支持动作降为 Secondary / Tertiary / Overflow。

年轻 Young

Electric Indigo 与局部 Cyan 建立年轻、活力和科技感，但识别度来自克制而稳定的使用，不来自满屏品牌色。

结果：Brand 主导身份和关键动作，Accent 只做局部信号。
一句话：冷静但不沉重，年轻但不轻浮，紧凑但不拥挤；颜色表达层级，Pattern 维持任务连续性。
Token 使用

先选 Semantic Role，再看具体值。不要因为“看起来淡”或“想突出”就直接取 Primitive 色阶。

动作层级

Primary 是当前最强下一步，不是“重要按钮”的统称；同一区域避免多个品牌实底按钮竞争。

UX 组合

跨组件问题先读 Core UX Pattern；业务可以扩展状态枚举，但不复制一套新的通用交互规则。

02

视觉基础 Foundations

所有产品共同消费的视觉语法。

Color · Default

默认 Brand = Electric Indigo #5B5EF7，用于最高优先级主动作、核心选中、全局导航与 Focus。品牌色不承担“所有可点击区域”的填充职责：Secondary Action 默认使用 Neutral-100，Info Container 默认使用 Neutral-100 + Brand foreground；Default Border 降至 Neutral-300，Placeholder 使用 Neutral-500。目标不是降低品牌识别，而是降低品牌色的出现面积与语义复用率。

Optional Theme Compatibility

Premium Gold · 土豪金兼容主题

这是一层兼容扩展，不是换肤覆盖。旧产品不启用 theme scope 时继续使用 Electric Indigo 体系；只有明确进入 Premium Gold scope 的页面或局部容器才切换到橙红品牌、香槟金价值表达、暖白背景与墨黑会员身份。Core 的动作层级与 UX Pattern 不随主题改变。

Compatible · Opt-in
Default · current baseline Com Design Electric Indigo

默认产品、通用能力与普通业务页继续使用这一套。当前基线强调“品牌识别不变、品牌色面积更克制”。

Optional · scoped Com Design Premium Gold

面向奖励、泡泡值、兑换码、会员与权益等高价值感场景。主题可以换映射，但 Primary 稀缺、Supporting Action 降权等规则保持不变。

橙红 = Brand / Action

品牌、主动作、Focus、Scoped Selection。它承担“我要做什么”，不是奖励本身。

香槟金 = Reward / Value

泡泡值、积分、奖励、权益、可兑换资产。不得替代 Warning，也不作为通用主按钮色。

墨黑 = Member Identity

只用于会员身份、等级与高价值权益容器。普通内容区域应回到暖白/标准 Surface。

语义不变：Success 仍是成功，Warning 仍是风险提醒，Danger 仍是错误/破坏动作。主题只改变合法的视觉映射，不重写 Core Component 或 UX Pattern。

推荐 Pattern

Reward Balance · 泡泡值

金色强调“价值”，主 CTA 仍走 Brand Action；不要整卡铺满高饱和金色。

Reward Earned · 获得奖励

Reward 表示获得了什么，Success 表示任务是否完成，两种语义不要混为一个绿色/金色状态。

Redemption Code · 兑换码

输入与提交沿用 Form / Button；金色只负责展示可兑换结果，失效/已使用必须走标准反馈语义。

Member Identity · 会员身份

墨黑是局部身份面，不是整 App 暗黑皮肤；等级、资产与权益可用香槟金做克制强调。

Benefit Card · 权益卡

标题、可用条件、有效期优先于装饰；不可用状态走 Disabled/Status，不发明“灰金色”。

Reward Ledger · 奖励流水

先靠 +/−、排版和来源区分收入/消耗。消费不是 Danger，除非真的发生异常。

Typography

默认系统 Sans，不靠特殊字体制造品牌感。正文基准为 16/24；14px 负责高频辅助与控件；24/28px 只给真正的页面标题或关键数字。

Spacing & Density

4px Grid

常用间距 4 / 8 / 12 / 16 / 20 / 24 / 32。Compact 控件 40px，大号 48px。

Radius

8 / 12 / 16 / Full

控件 8、容器 12、浮层 16、Pill full。圆角承担层级，不承担“可爱感”。

Elevation

Flat-first

普通卡片和按钮 resting 态不默认加阴影；只有真实悬浮关系才使用 elevation。

Touch Target

Visual ≠ Hit Area

视觉控件可保持紧凑，命中区域仍需独立满足 iOS / Android 平台要求。

03

Core UX Patterns

Component 解决一个控件怎么做；Pattern 解决跨组件、跨状态、跨页面的任务怎样持续工作。Pattern 不计入 33 个 Core Component。

01

Status Composition · 状态组合

状态必须能被文字独立理解；需要时补解释、证据与恢复动作。不要用“彩色卡 + 彩色 Tag + 彩色图标”重复表达同一件事。

02

Search Pattern · 搜索

Query、Loading、Zero Result、Error 与 Detail Return 属于同一搜索任务。返回详情后，只要任务仍在进行，就应保留用户查询。

03

Collection Filter · 集合筛选

页面持有已提交筛选真相，Sheet 只持有草稿；Active Conditions 可回显与删除，详情返回后保持筛选上下文。

04

State to Action · 状态到动作

从账号、权限、资格或流程状态推导当前可做什么。通常只突出一个最高优先级动作；Supporting Action 降为 Secondary / Tertiary。

05

Intent Continuity / Handoff · 意图连续与回流

登录、授权或外部流程不能抹掉用户原来的任务。保存安全 Return Target，回流后更新已有业务主体，不制造第二份状态。

06

Contextual Next Step · 上下文下一步

长流程持续回答“我现在该做什么”。保留当前实体上下文，从权威状态推导进度和下一步，而不是做一张等权按钮仪表盘。

组合底线：Section-before-Card、反馈按打断成本升级、同一时刻只保留一个 Blocking Modal、Loading / Empty / Error 不互相冒充。查看 6 个 Pattern Preview ↗

采用验证 Adoption

设计系统必须被真实产品消费，而不是只在规范页里成立。

Completed首批接入实验

卡博士

第一批接入实验已宣告完成。这个案例的意义是验证：产品可以消费 Com Design Core，同时保留自己的业务内容、插画、活动视觉与领域表达。

边界

产品适配可以组合、扩展 Core；产品特有视觉和业务状态不得反写公司级 Foundation 与 Core Component 契约。

真实产品的实践可以反哺 Token 使用治理和 UX Pattern；但业务组件与业务状态枚举不因此自动晋升为 Core。
