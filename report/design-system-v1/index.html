01

设计原则

先统一判断方式，再统一组件外观。

清晰 Clear

先建立信息层级，再考虑装饰。正文、辅助信息、动作、状态有稳定优先级。

结果：低噪声背景、有限高纯度色、明确标题层级。

轻快 Light

高信息密度不等于沉重。默认主题靠冷调 Neutral、留白和薄边界保持呼吸感；兼容主题可调整色温，但不改信息层级。

结果：Flat-first；普通信息层不依赖阴影。

高效 Efficient

默认 Compact，但视觉尺寸与触摸命中区域分离，不用缩小可用性换密度。

结果：40px 常规控件；命中区域独立满足平台下限。

年轻 Young

默认主题由 Electric Indigo 与局部 Cyan 建立节奏；可选主题可以改变品牌气质，但不能破坏 Core 组件和状态语义。

结果：Brand 主导身份，Accent 只做局部信号。
一句话：冷静但不沉重，年轻但不轻浮，紧凑但不拥挤；主题可以变，判断方式不变。
设计师

先看 Foundation 与 Pattern，再从左侧组件树确认具体控件边界。

产品

先确认交互属于导航、反馈、输入还是业务扩展，不用视觉相似代替语义判断。

研发

实现以 design-source 的契约与变量为准；本文档用于理解设计意图，不替代机器真相。

视觉基础 Foundations

所有产品共同消费的视觉语法。

Color · Default

默认 Brand = Electric Indigo #5B5EF7，用于主动作、核心选中和全局导航身份。Accent = Cyan #16BFD3 只做局部强调、进度、数据和受约束的产品 Pattern。默认色系仍是 Com Design 的基线，不因 Premium Gold 的加入被替换。

Optional Theme Compatibility

Premium Gold · 土豪金兼容主题

这是一层兼容扩展，不是换肤覆盖。旧产品不启用 theme scope 时，Brand、Surface、Button、Status 全部继续使用原来的 Electric Indigo 体系；只有明确进入 Premium Gold scope 的页面或局部容器才切换到橙红品牌、香槟金价值表达、暖白背景与墨黑会员身份。

Compatible · Opt-in
Default · unchanged Com Design Electric Indigo

默认产品、通用后台能力、普通业务页继续使用这一套。没有迁移成本，也没有“全公司改成金色”的隐含要求。

Optional · scoped Com Design Premium Gold

面向奖励、泡泡值、兑换码、会员与权益等高价值感场景。主按钮使用 Brand 600 #D63D10，避免 #ED4D1B + 白色普通字号的对比度不足。

橙红 = Brand / Action

品牌、主动作、Focus、Scoped Selection。它承担“我要做什么”，不是奖励本身。

香槟金 = Reward / Value

泡泡值、积分、奖励、权益、可兑换资产。不得替代 Warning，也不作为通用主按钮色。

墨黑 = Member Identity

只用于会员身份、等级与高价值权益容器。普通内容区域应回到暖白/标准 Surface。

语义不变：Success 仍是成功，Warning 仍是风险提醒，Danger 仍是错误/破坏动作。Premium Gold 只扩展 Brand / Reward / Member 表达，绝不拿“金色看起来贵”去重定义状态色。

推荐 Pattern

Reward Balance · 泡泡值

金色强调“价值”，主 CTA 仍走 Brand Action；不要整卡铺满高饱和金色。

Reward Earned · 获得奖励

Reward 表示获得了什么，Success 表示任务是否完成，两种语义不要混为一个绿色/金色状态。

Redemption Code · 兑换码

输入与提交沿用 Form / Button；金色只负责展示可兑换结果，失效/已使用必须走标准反馈语义。

Member Identity · 会员身份

墨黑是局部身份面，不是整 App 暗黑皮肤；等级、资产与权益可用香槟金做克制强调。

Benefit Card · 权益卡

标题、可用条件、有效期优先于装饰；不可用状态走 Disabled/Status，不发明“灰金色”。

Reward Ledger · 奖励流水

先靠 +/−、排版和来源区分收入/消耗。消费不是 Danger，除非真的发生异常。

Typography

默认系统 Sans，不靠特殊字体制造品牌感。正文基准为 16/24；14px 负责高频辅助与控件；24/28px 只给真正的页面标题或关键数字。

Spacing & Density

4px Grid

常用间距 4 / 8 / 12 / 16 / 20 / 24 / 32。Compact 控件 40px，大号 48px。

Radius

8 / 12 / 16 / Full

控件 8、容器 12、浮层 16、Pill full。圆角承担层级，不承担“可爱感”。

Elevation

Flat-first

普通卡片和按钮 resting 态不默认加阴影；只有真实悬浮关系才使用 elevation。

Touch Target

Visual ≠ Hit Area

视觉控件可保持紧凑，命中区域仍需独立满足 iOS / Android 平台要求。

03

设计模式 Design Patterns

组件解决一个控件怎么做；Pattern 解决一组控件怎样一起工作。

01

信息组织

Section-before-Card。先用标题、间距、Divider 建层级；只有真正独立的实体才进入 Card。

02

表单

Label → Control → Helper / Error 保持稳定。字段错误优先就地解释，不轻易升级成 Toast 或 Dialog。

03

导航

Bottom Navigation 管顶层目的地；Tabs 管同层视图；Segmented Control 管局部模式，三者不可因外观相似互换。

04

搜索

Search 不是普通 Input。Query、Clear、Loading、No Results 都属于完整搜索上下文。

05

反馈层级

Field / Helper → Inline Alert → Toast / Snackbar → Dialog。越往后，打断成本越高。

06

Overlay

同一时刻只保留一个 Blocking Modal；Dialog 不叠 Dialog，Sheet 不叠 Sheet。

07

Loading / Empty / Error

结构已知用 Skeleton；未知等待用 Loading；没有内容用 Empty；失败必须给 Recovery。

08

Progress

Progress 表示可计算进度；Stepper 表示有限步骤；Timeline 表示已经发生的事件历史。

09

Status

Status 是语义组合，不是“彩色胶囊”。颜色永远不能成为唯一信号。

05

采用验证 Adoption

设计系统必须被真实产品消费，而不是只在规范页里成立。

Completed首批接入实验

卡博士

第一批接入实验已宣告完成。这个案例的意义是验证：产品可以消费 Com Design Core，同时保留自己的业务内容、插画、活动视觉与领域表达。

边界

产品适配可以组合、扩展 Core；产品特有视觉和业务状态不得反写公司级 Foundation 与 Core Component 契约。

后续产品接入时，优先复用这次形成的判断方法，而不是复制卡博士页面本身。
