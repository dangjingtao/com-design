01

设计原则

先统一判断方式，再统一组件外观。

清晰 Clear

先建立信息层级，再考虑装饰。正文、辅助信息、动作、状态有稳定优先级。

结果：低噪声背景、有限高纯度色、明确标题层级。

轻快 Light

高信息密度不等于沉重。靠冷调 Neutral、留白和薄边界保持呼吸感。

结果：Flat-first；普通信息层不依赖阴影。

高效 Efficient

默认 Compact，但视觉尺寸与触摸命中区域分离，不用缩小可用性换密度。

结果：40px 常规控件；命中区域独立满足平台下限。

年轻 Young

年轻感来自 Electric Indigo 与局部 Cyan 的节奏，不靠霓虹、渐变和过度软化。

结果：Brand 主导身份，Accent 只做局部信号。
一句话：冷静但不沉重，年轻但不轻浮，紧凑但不拥挤。
设计师

先看 Foundation 与 Pattern，再从左侧组件树确认具体控件边界。

产品

先确认交互属于导航、反馈、输入还是业务扩展，不用视觉相似代替语义判断。

研发

实现以 design-source 的契约与变量为准；本文档用于理解设计意图，不替代机器真相。

视觉基础 Foundations

所有产品共同消费的视觉语法。

Color

Brand = Electric Indigo #5B5EF7，用于主动作、核心选中和全局导航身份。Accent = Cyan #16BFD3 只做局部强调、进度、数据和受约束的产品 Pattern。

Typography

默认系统 Sans，不靠特殊字体制造品牌感。正文基准为 16/24；14px 负责高频辅助与控件；24/28px 只给真正的页面标题或关键数字。

Spacing & Density

4px Grid

常用间距 4 / 8 / 12 / 16 / 20 / 24 / 32。Compact 控件 40px，大号 48px。

Radius

8 / 12 / 16 / Full

控件 8、容器 12、浮层 16、Pill full。圆角承担层级，不承担“可爱感”。

Elevation

Flat-first

普通卡片和按钮 resting 态不默认加阴影；只有真实悬浮关系才使用 elevation。

Touch Target

Visual ≠ Hit Area

视觉控件可保持紧凑，命中区域仍需独立满足 iOS / Android 平台要求。

03

设计模式 Design Patterns

组件解决一个控件怎么做；Pattern 解决一组控件怎样一起工作。

01

信息组织

Section-before-Card。先用标题、间距、Divider 建层级；只有真正独立的实体才进入 Card。

02

表单

Label → Control → Helper / Error 保持稳定。字段错误优先就地解释，不轻易升级成 Toast 或 Dialog。

03

导航

Bottom Navigation 管顶层目的地；Tabs 管同层视图；Segmented Control 管局部模式，三者不可因外观相似互换。

04

搜索

Search 不是普通 Input。Query、Clear、Loading、No Results 都属于完整搜索上下文。

05

反馈层级

Field / Helper → Inline Alert → Toast / Snackbar → Dialog。越往后，打断成本越高。

06

Overlay

同一时刻只保留一个 Blocking Modal；Dialog 不叠 Dialog，Sheet 不叠 Sheet。

07

Loading / Empty / Error

结构已知用 Skeleton；未知等待用 Loading；没有内容用 Empty；失败必须给 Recovery。

08

Progress

Progress 表示可计算进度；Stepper 表示有限步骤；Timeline 表示已经发生的事件历史。

09

Status

Status 是语义组合，不是“彩色胶囊”。颜色永远不能成为唯一信号。

采用验证 Adoption

设计系统必须被真实产品消费，而不是只在规范页里成立。

Completed首批接入实验

卡博士

第一批接入实验已宣告完成。这个案例的意义是验证：产品可以消费 Com Design Core，同时保留自己的业务内容、插画、活动视觉与领域表达。

边界

产品适配可以组合、扩展 Core；产品特有视觉和业务状态不得反写公司级 Foundation 与 Core Component 契约。

后续产品接入时，优先复用这次形成的判断方法，而不是复制卡博士页面本身。
