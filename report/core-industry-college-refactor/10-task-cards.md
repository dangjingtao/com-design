# 核心产业学院 App 重构任务卡

> **强制规则：所有施工线程先执行 `T0-construction-preflight.md`，再进入自己的任务卡；每张任务卡开始前、提交前都必须重新检查 `00-master-outline.md`。**
> 不允许脱离总纲单独优化页面；不允许以“页面画完”替代“项目可运行、动线可点击”。

## T0 — 所有施工线程开工前置任务

T0 是 T01–T05、返修线程以及任何直接修改原型工程线程的统一开工门禁，**不计入 T01–T05 五张施工卡额度**。

执行清单见：`T0-construction-preflight.md`。

核心要求：

- 先确认当前分支 HEAD、任务范围、上游 PASS 状态和不可修改边界。
- 读总纲、自己的任务卡/评审卡、T01 基线、相关旧页映射、最近已 PASS 的实现/评审、当前实际代码和 Com Design。
- 开工前明确目标、范围、进入/完成动线、关键状态、冻结契约、未决项和预计改动面。
- 并行施工不得覆盖其它线程提交；共享 route/state/provider 需要变化时先交评审线程判断。
- 环境无法验证的项目必须如实标记，不得伪造 build / walkthrough 结果。

**完成标准**：施工线程先在对话中给出 `T0 DONE` 开工摘要，再开始业务实现；T0 默认不单独产出业务代码或报告。

## T01 — 页面总图、路由与工程基线

**目标**：吃透旧原型，建立旧 -> 新映射，并搭出可继续开发的原型工程骨架。

**执行**
- 盘点旧原型全部功能、页面、状态、入口和跳转。
- 输出旧 -> 新页面映射；标记保留 / 合并 / 拆分 / 归档。
- 重建一级导航、公共平台、赛事上下文和“我的”结构。
- 把总纲 5 条母动线落成可检查的 Flow Map。
- 建立前端项目骨架、路由规则、目录规范、mock data/state 组织方式。
- 输出 Com Design Core 可直接复用项与必要 Product Pattern 缺口清单。

**交付**
- 可启动的前端原型工程骨架。
- 页面树 / 路由清单。
- 旧 -> 新映射表。
- 5 条母动线图。
- mock 数据/状态模型基线。
- 待决策项清单，禁止执行线程擅自补产品定义。

**完成标准**：在大面积实现页面前，已经知道约 150 页/状态分别属于哪条业务链、走什么路由、从哪里来、到哪里去，并且项目能实际运行。

## T02 — 公共平台：首页 / 赛事发现 / 企业与机会

**目标**：把“参赛 + 就业 / 实习”做成可实际点击体验的第一层产品心智。

**执行**
- 实现首页信息优先级与首屏动作。
- 实现赛事发现、赛事详情、我的赛事入口。
- 实现企业、实习/岗位发现、机会详情、企业详情、关注关系。
- 保留课程、权益、资料等公共能力，但降到支撑层。
- 实现未登录、无赛事身份、无数据、搜索/筛选无结果等状态。
- 页面优先复用组件和 mock data，不复制静态页面。

**动线重点**
- 首页 -> 赛事详情 -> 报名/加入赛事。
- 首页 -> 实习/岗位 -> 详情 -> 企业 -> 投递入口。
- 首页 -> 我的赛事 -> 当前赛事。

**完成标准**：浏览器中可连续点击完成上述路径；新用户不需要解释就能找到“有什么比赛”“有什么实习”“我正在参加什么”。

## T03 — 三创赛生命周期与创赛工坊

**目标**：实现完整赛事上下文，并把工坊做成真正可操作的陪跑流程。

**执行**
- 串起赛事详情 -> 报名 -> 审核 -> 身份授予 -> 团队/项目 -> 赛事能力。
- 明确响应式报名与原型原生页面边界，并实现清晰的跳入/回流模拟。
- 实现三创赛空间内：状态、团队、项目、赛事资料、赛事权益、任务、成绩/证书。
- 实现创赛工坊首页与 S1–S6：优先“下一步做什么”，修复任务串线。
- 用 mock state 支持无身份、审核中、被拒、赛事未开始、进行中、已结束、权限回收等状态切换。

**动线重点**
- 报名回流后必须自然进入赛事上下文。
- 工坊任何任务都必须有进入、执行、确认、成果、继续下一步、返回路径。
- 赛事结束后必须能转入长期资产。

**完成标准**：完整走一遍三创赛，不需要靠记忆入口；不同状态可以在原型中实际触发或切换。

## T04 — 长期资产与支撑系统

**目标**：把课程、权益、可信成果、任务、个人资料等实现为主业务的可交互支撑层。

**执行**
- 课程：公共 / 赛事来源、学习进度、考试/成绩、证书、长期保留。
- 权益：平台 / 赛事 / 企业 / 活动来源，领取、资格、兑换/核销、失效状态。
- 可信项目/可信成果：连接赛事成绩、证书、项目经历与履历表达。
- 我的：赛事经历、学习成果、证书、收藏/关注、投递记录、长期简历。
- 任务专区：仅在业务定义明确后实现；未明确不得用 UI 猜需求。
- 相同卡片、列表、状态组件统一抽象，避免模块各写一套。

**动线重点**
- 赛事/课程/权益/企业产生的结果都能回到“我的长期资产”。
- 长期简历能吸收可信经历，但最终表达由学生确认和编辑。

**完成标准**：比赛结束后，学生资产仍可访问；关键状态和动作可点击演示。

## T05 — 全量页面、交互回归与工程收口

**目标**：完成全量中保真可交互原型，并把它收成一个方便后续继续修改的前端项目。

**执行**
- 按 T01 页面树补齐剩余全部页面和必要状态，不机械追求 150 数字。
- 全局补齐 loading / empty / error / permission / disabled / expired / success 等状态。
- 统一返回、关闭、取消、提交成功、失败重试、深层页面退出逻辑。
- 映射 Com Design：组件、字号、间距、圆角、surface/border、触控区。
- 清理重复页面代码、重复 mock 数据、无语义路由和超大组件。
- README 写明安装、启动、构建、页面入口、mock 状态切换方式。
- 实际构建项目，并按总纲 5 条母动线逐条回归。

**完成标准**
- 项目可安装、启动、构建。
- 旧功能覆盖无无故缺失。
- 5 条母动线从头到尾连续点击走通。
- 不存在明显孤岛页、死路、串线、赛事上下文错乱。
- 代码结构清楚，后期可直接继续改，而不是一次性演示代码。
- 中保真视觉统一建立在结构和交互正确之后。
