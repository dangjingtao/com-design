# 核心产业学院 App 重构任务卡

> **强制规则：每张任务卡开始前、提交前都必须重新检查 `00-master-outline.md`。**
> 不允许脱离总纲单独优化页面；不允许以“视觉完成”替代动线完成。

## T01 — 页面总图与动线基线

**目标**：先把旧原型吃透，建立旧 -> 新映射和整套页面树。

**执行**
- 盘点旧原型全部功能、页面、状态、入口和跳转。
- 输出旧 -> 新页面映射；标记保留 / 合并 / 拆分 / 归档。
- 重建一级导航、公共平台、赛事上下文和“我的”结构。
- 把总纲 5 条母动线落成可检查的 Flow Map。

**交付**
- 页面树 / 页面清单。
- 旧 -> 新映射表。
- 5 条母动线图。
- 待决策项清单，禁止执行线程擅自补产品定义。

**完成标准**：未开始大面积画页面前，已知道约 150 页分别属于哪条业务链、从哪里来、到哪里去。

---

## T02 — 公共平台：首页 / 赛事发现 / 企业与机会

**目标**：把“参赛 + 就业 / 实习”真正变成用户第一层心智。

**执行**
- 重构首页信息优先级与首屏动作。
- 重构赛事发现、赛事详情、我的赛事入口。
- 重构企业、实习/岗位发现、机会详情、企业详情、关注关系。
- 保留课程、权益、资料等公共能力，但降到支撑层，不抢主叙事。
- 补全未登录、无赛事身份、无数据、搜索/筛选无结果等状态。

**动线重点**
- 首页 -> 赛事详情 -> 报名/加入赛事。
- 首页 -> 实习/岗位 -> 详情 -> 企业 -> 投递。
- 首页 -> 我的赛事 -> 当前赛事。

**完成标准**：新用户不需要解释就能找到“有什么比赛”“有什么实习”“我正在参加什么”。

---

## T03 — 三创赛生命周期与创赛工坊

**目标**：让三创赛从零散入口变成完整赛事上下文，并把工坊做成真正陪跑动线。

**执行**
- 串起赛事详情 -> 报名 -> 审核 -> 身份授予 -> 团队/项目 -> 赛事能力。
- 明确响应式报名与 App 原生页面边界。
- 重构三创赛空间内：状态、团队、项目、赛事资料、赛事权益、任务、成绩/证书。
- 重构创赛工坊首页与 S1–S6：优先“下一步做什么”，修复任务串线。
- 处理无身份、审核中、被拒、赛事未开始、进行中、已结束、权限回收等状态。

**动线重点**
- 报名回流后必须自然进入赛事上下文。
- 工坊任何任务都必须有进入、执行、确认、成果、继续下一步、返回路径。
- 赛事结束后必须能转入长期资产，而不是把用户留在失效赛事页。

**完成标准**：完整走一遍三创赛，不需要靠“记住哪个入口在哪”才能继续。

---

## T04 — 长期资产与支撑系统

**目标**：把旧原型已有的课程、权益、可信成果、任务、个人资料等重新挂回真实用户任务。

**执行**
- 课程：公共 / 赛事来源、学习进度、考试/成绩、证书、长期保留。
- 权益：平台 / 赛事 / 企业 / 活动来源，领取、资格、兑换/核销、失效状态。
- 可信项目/可信成果：连接赛事成绩、证书、项目经历与履历表达，避免孤岛。
- 我的：赛事经历、学习成果、证书、收藏/关注、投递记录、长期简历。
- 任务专区：仅在业务定义明确后落页；未明确不得用 UI 猜需求。

**动线重点**
- 赛事/课程/权益/企业产生的结果都能回到“我的长期资产”。
- 长期简历能吸收可信经历，但最终表达由学生确认和编辑。

**完成标准**：比赛结束后，学生仍有东西留下，也仍有理由回来。

---

## T05 — 全量页面重构、状态补齐与 Com Design 收口

**目标**：完成全量高保真原型，并把 5 条母动线连成真正可验收的 App。

**执行**
- 按 T01 页面树完成剩余全部页面和必要状态，不机械追求 150 数字。
- 全局补齐 loading / empty / error / permission / disabled / expired / success 等状态。
- 统一返回、关闭、取消、提交成功、失败重试、深层页面退出逻辑。
- 映射 Com Design：组件、字号、间距、圆角、surface/border、触控区。
- 建立可点击原型，按总纲 5 条母动线逐条回归。

**完成标准**
- 旧功能覆盖无无故缺失。
- 5 条母动线从头到尾连续走通。
- 不存在明显孤岛页、死路、串线、赛事上下文错乱。
- 视觉统一建立在结构正确之后，而不是遮盖结构问题。
