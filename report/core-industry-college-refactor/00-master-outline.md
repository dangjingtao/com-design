# 核心产业学院 App 重构总纲

> Branch: `core-industry-college-refactor`
> Role: 本文件是本轮重构的最高约束。所有任务卡执行前、提交前必须检查；所有评审卡必须以本文件为第一验收依据。

## 1. 最终交付定义

本轮不是交付静态设计稿，而是交付一个**可运行、可点击、方便继续修改的移动端中保真前端原型项目**。

可将其直接理解为一个 Tailwind 前端项目：源码是交付物，浏览器中的交互原型是运行结果。

要求：

1. 约 140–150 页/状态由真实路由、组件和状态组织，不以截图或散页替代。
2. 关键按钮、列表项、Tab、返回、弹层、表单、筛选、状态切换均可实际交互。
3. 五条母动线可连续点击走通。
4. 页面应组件化、数据与视图尽量分离，后续产品修改不需要逐页硬改。
5. 使用 Com Design Core 作为视觉/组件基础，产品侧只做必要扩展，不修改 Core 真相源。
6. 中保真即可：优先结构、层级、动线、状态和可维护性，不投入复杂品牌物料与高保真装饰。

### 默认工程形态

如无更合适的现有项目骨架，采用：

- Vite
- React + TypeScript
- Tailwind CSS
- React Router（或等价轻量路由）
- 本地 mock data / mock state，不依赖后端即可完整演示

原型代码建议独立放置，例如 `prototype/core-industry-college/`，避免污染 Com Design Core。

## 2. 产品目标

不是重做业务，也不是继续加功能；是在旧原型功能覆盖基本充足的前提下，重构产品骨架、页面组织和用户动线。

核心目标：

1. 学生第一眼理解平台主轴：**参赛 + 就业 / 实习**。
2. 明确 **公共平台** 与 **赛事生命周期能力** 的边界。
3. 保留旧原型已有功能，不因重构造成业务能力丢失。
4. 全量页面回归 Com Design，并形成可连续走通的真实移动端动线。
5. 最终原型本身具备继续迭代的工程可维护性。

## 3. 真相源优先级

1. 旧 Mockplus 原型：已有功能、页面、状态、字段和流程覆盖的功能真相源。
2. `report/product-reviews/2026-08-17-formal-prototype-review.md`：本轮重构问题与产品骨架真相源。
3. `report/product-reviews/2026-08-15-product-background-interview.md` 及补充稿：业务边界与尚未确认事项。
4. `design.md` + `design-source/`：视觉、组件、交互与 token 真相源。

发生冲突时：**功能是否存在看旧原型；功能该放哪里、怎么串看正式评审稿；怎么呈现看 Com Design。**

## 4. 不可破坏的产品原则

- App 账号长期存在；赛事身份按赛事生命周期存在。
- 无赛事身份用户仍可正常使用公共平台。
- 一个账号可关联多个赛事身份。
- 三创赛是首个强入口，不得把平台结构写死成三创赛专属。
- 参赛项目主要服务赛事生命周期；赛后沉淀经历、成绩、证书、课程成果等长期资产。
- 创赛工坊是三创赛赛事陪跑能力，不是首期全平台通用 AI。
- 企业首先是赛事 / 权益 / 课程 / 活动 / 机会的资源与品牌主体，不只是招聘公司。
- 报名复杂表单优先复用现有响应式报名层；原型中需清楚表达进入、返回和报名结果回流。
- 不以页面数量为目标；允许合并、拆分，但旧功能覆盖不得无理由缩水。

## 5. 五条必须走通的母动线

### A. 新用户公共平台
`注册/登录 -> 首页 -> 发现赛事/机会 -> 查看详情 -> 继续使用课程/权益/企业/个人资产`

### B. 三创赛参赛
`赛事发现 -> 三创赛详情 -> 报名入口 -> 响应式报名 -> 审核/报名状态回流 -> 获得赛事身份 -> 进入赛事上下文`

### C. 赛事陪跑
`我的赛事 -> 当前赛事 -> 当前项目/状态 -> 创赛工坊 -> 下一步任务 -> 执行/确认 -> 成果 -> 继续推进 -> 成绩/证书`

### D. 就业 / 实习
`首页/机会入口 -> 实习/岗位发现 -> 机会详情 -> 企业详情 -> 使用长期简历 -> 投递 -> 投递记录/状态`

### E. 赛后长期资产
`赛事结束 -> 赛事权限回收 -> 经历/项目摘要/成绩/证书/课程成果 -> 我的长期资产/简历表达`

任何局部页面设计或实现不得破坏这五条母动线。

## 6. 页面与代码级规则

每个页面必须回答：

- 用户从哪里来？
- 当前处于公共平台还是某个赛事上下文？
- 当前最重要的一个主动作是什么？
- 完成后去哪里？
- 返回路径是什么？
- 无权限 / 空数据 / 审核中 / 已结束 / 异常时怎么走？

同时要求：

- 相同业务对象不得复制成多套近似页面代码；优先组件 + props / data 驱动。
- 页面状态优先由 mock 数据/状态控制，而不是复制多个静态 HTML 页面。
- 路由命名和目录结构必须可读，禁止用 page1/page2 等无语义编号作为主要结构。
- 不允许用一个超大组件硬塞全部页面。
- 不为原型引入不必要的后端、鉴权或复杂状态框架。
- 禁止出现“页面本身合理，但前后无路”的孤岛页面。

## 7. 全局验收

最终交付至少满足：

- 项目可安装、启动、构建；README 说明运行方式。
- 旧原型功能有旧 -> 新页面映射，删除项有明确理由。
- 五条母动线可从头连续点击走通。
- 关键交互不是视觉假按钮。
- 首页和一级导航不再让课程/学力值压过参赛与就业机会。
- 公共能力与赛事专属能力不会串线。
- 创赛工坊明确赛事归属，并突出“下一步做什么”。
- 企业、机会、权益、课程、可信成果能与学生真实任务发生关系。
- 关键状态完整，不只实现 happy path。
- 关键页面符合 Com Design 的 typography / spacing / radius / surface / interaction target / component mapping。
- 组件、路由、mock data、页面结构清楚，后续可继续修改而无需推翻重写。
