# 核心产业学院 App 重构总纲

> Branch: `core-industry-college-refactor`
> Role: 本文件是本轮重构的最高约束。所有任务卡执行前、提交前必须检查；所有评审卡必须以本文件为第一验收依据。

## 1. 目标

不是重做业务，也不是继续加功能；是在旧原型功能覆盖基本充足的前提下，重构约 140–150 页的产品骨架、页面组织和用户动线。

核心目标只有四个：

1. 学生第一眼理解平台主轴：**参赛 + 就业 / 实习**。
2. 明确 **公共平台** 与 **赛事生命周期能力** 的边界。
3. 保留旧原型已有功能，不因重构造成业务能力丢失。
4. 全量页面回归 Com Design，并形成可连续走通的真实移动端动线。

## 2. 真相源优先级

1. 旧 Mockplus 原型：已有功能、页面、状态、字段和流程覆盖的功能真相源。
2. `report/product-reviews/2026-08-17-formal-prototype-review.md`：本轮重构问题与产品骨架真相源。
3. `report/product-reviews/2026-08-15-product-background-interview.md` 及补充稿：业务边界与尚未确认事项。
4. `design.md` + `design-source/`：视觉、组件、交互与 token 真相源。

发生冲突时：**功能是否存在看旧原型；功能该放哪里、怎么串看正式评审稿；怎么画看 Com Design。**

## 3. 不可破坏的产品原则

- App 账号长期存在；赛事身份按赛事生命周期存在。
- 无赛事身份用户仍可正常使用公共平台。
- 一个账号可关联多个赛事身份。
- 三创赛是首个强入口，不得把平台结构写死成三创赛专属。
- 参赛项目主要服务赛事生命周期；赛后沉淀经历、成绩、证书、课程成果等长期资产。
- 创赛工坊是三创赛赛事陪跑能力，不是首期全平台通用 AI。
- 企业首先是赛事 / 权益 / 课程 / 活动 / 机会的资源与品牌主体，不只是招聘公司。
- 报名复杂表单优先复用现有响应式报名层；App 原生承接身份、状态、团队和后续赛事能力。
- 不以页面数量为目标；允许合并、拆分，但旧功能覆盖不得无理由缩水。

## 4. 五条必须走通的母动线

### A. 新用户公共平台
`注册/登录 -> 首页 -> 发现赛事/机会 -> 查看详情 -> 继续使用课程/权益/企业/个人资产`

### B. 三创赛参赛
`赛事发现 -> 三创赛详情 -> 报名入口 -> 响应式报名 -> 审核/报名状态回流 -> 获得赛事身份 -> 进入赛事上下文`

### C. 赛事陪跑
`我的赛事 -> 当前赛事 -> 当前项目/状态 -> 创赛工坊 -> 下一步任务 -> 执行/确认 -> 成果 -> 继续推进 -> 成绩/证书`

### D. 就业 / 实习
`首页/机会入口 -> 实习/岗位发现 -> 机会详情 -> 企业详情 -> 使用长期简历 -> 投递 -> 投递记录/状态`

### E. 赛后长期资产
`赛事结束 -> 赛事权限回收 -> 经历/项目摘要/成绩/证书/课程成果 -> 我的长期资产/简历表达`

任何局部页面设计不得破坏这五条母动线。

## 5. 页面级重构规则

每个页面必须回答：

- 用户从哪里来？
- 当前处于公共平台还是某个赛事上下文？
- 当前最重要的一个主动作是什么？
- 完成后去哪里？
- 返回路径是什么？
- 无权限 / 空数据 / 审核中 / 已结束 / 异常时怎么走？

禁止出现“页面本身合理，但前后无路”的孤岛页面。

## 6. 全局验收

最终交付至少满足：

- 旧原型功能有旧 -> 新页面映射，删除项有明确理由。
- 五条母动线可从头连续走通。
- 首页和一级导航不再让课程/学力值压过参赛与就业机会。
- 公共能力与赛事专属能力不会串线。
- 创赛工坊明确赛事归属，并突出“下一步做什么”。
- 企业、机会、权益、课程、可信成果能与学生真实任务发生关系。
- 关键状态完整，不只设计 happy path。
- 关键页面符合 Com Design 的 typography / spacing / radius / surface / interaction target / component mapping。
