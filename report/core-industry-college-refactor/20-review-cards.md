# 核心产业学院 App 重构评审卡

> **评审线程职责：每次评审先检查 `00-master-outline.md`，再检查对应任务卡。**
> **施工卡/返修评审同时检查 `T0-construction-preflight.md`：是否读了最新 HEAD、是否守住上游冻结契约、是否越界修改其它线程领域、是否伪造未执行的验证。**
> 评审优先级固定为：**总纲一致性 > 母动线 > 功能覆盖 > 可交互性 > 状态完整 > 可维护性 > Com Design 一致性**。
> 页面好看但走不通，或只能看不能点，直接不通过。

## R01 — T01 页面总图 / 路由 / 工程基线评审

**必查总纲**：产品原则、5 条母动线、最终交付定义、真相源优先级。

**检查**
- 旧功能是否全部有去向；删除/归档是否有理由。
- 一级导航是否服务“参赛 + 就业 / 实习”。
- 公共平台与赛事上下文是否分清。
- 5 条母动线是否都有入口、主动作、结果和返回路径。
- 页面树是否已经落成可理解的路由结构。
- 工程骨架是否能启动，目录、组件、mock data/state 是否有清晰边界。
- 是否列出 Com Design 直接复用项和必要 Product Pattern 缺口。
- 是否提前暴露需要产品拍板的问题，而不是偷偷假设。

**拒绝条件**：只有模块清单没有真实 Flow；没有可运行工程骨架；或用 page1/page2 等无语义方式堆页面。

---

## R02 — T02 公共平台评审

**必查总纲**：A 新用户公共平台、B 三创赛参赛入口、D 就业 / 实习。

**检查**
- 首页第一屏能否快速理解“比赛 + 实习/就业”。
- 无赛事身份用户是否仍然是完整用户，不是残缺态。
- 赛事发现 -> 详情 -> 报名入口是否可连续点击走通。
- 机会发现 -> 详情 -> 企业 -> 投递入口是否可连续点击走通。
- 企业是否表达资源/品牌/机会关系，而非单纯招聘名录。
- 课程、权益、学习数据是否重新回到支撑层。
- 搜索、筛选、空结果、未登录等状态是否可实际触发或展示。
- 页面是否复用组件和数据模型，而非复制近似页面代码。

**拒绝条件**：需要用户频繁返回首页重新找入口；关键按钮是假交互；或相同页面结构被复制多份硬改。

---

## R03 — T03 三创赛 / 创赛工坊评审

**必查总纲**：B 三创赛参赛、C 赛事陪跑、E 赛后长期资产。

**检查**
- 报名响应式层与原型原生层是否无双轨冲突。
- 报名成功/审核完成后是否明确获得赛事身份并进入正确赛事。
- 多赛事模型是否成立，没有把账号写死成三创赛用户。
- 工坊是否明确“当前赛事 / 当前项目 / 当前下一步”。
- S1–S6 是否无串线，每个任务都有完整可点击回路。
- 无权限、审核中、被拒、结束、回收权限等状态是否由清晰 mock state 支撑。
- 赛事结束后是否自然进入长期资产，而不是停在失效页面。

**拒绝条件**：工坊仍像功能宫格；任务按钮不能实际推进状态；或赛事结束后用户/资产一起“消失”。

---

## R04 — T04 长期资产 / 支撑系统评审

**必查总纲**：长期账号原则、企业原则、赛后长期资产动线。

**检查**
- 课程、权益、可信成果、企业资源是否都能解释“为什么此时给用户看”。
- 赛事结束后课程进度、成绩、证书、经历是否仍可访问。
- 权益资格/领取/兑换/核销/失效是否状态完整且可演示。
- 投递记录、赛事经历、学习成果是否能汇入长期简历/个人资产。
- 可信项目是否连接真实结果，而不是另起孤立系统。
- “任务专区”若业务仍未定义，是否保持未实现而非猜测。
- 同类卡片、列表、状态是否复用统一组件。

**拒绝条件**：支撑模块再次反客为主；同一资产在多个模块重复、互不相认；或状态只是静态样张不能切换。

---

## R05 — T05 全量终审

**必查总纲**：全文逐项检查，不接受抽样代替母动线回归。

**必须实走 5 条母动线**
1. 新用户公共平台。
2. 三创赛报名与身份获得。
3. 赛事陪跑与创赛工坊。
4. 就业 / 实习投递。
5. 赛后长期资产。

**工程验收**
- 项目可按 README 完成安装、启动、构建。
- 路由、页面、组件、mock data/state 目录清楚。
- 不存在一个超大组件承载全部页面。
- 不存在大量复制页面只改文案/数据的实现。
- 关键状态可由 mock 数据或状态开关重现。
- 后续修改导航、卡片结构、业务字段时，能通过改组件/数据影响相关页面，而不是逐页返工。

**产品与交互验收**
- 旧 -> 新功能覆盖无无故缺口。
- 页面不存在明显死路、孤岛、错返回、串赛事上下文。
- 主按钮与下一步一致，不用用户猜。
- 空/错/禁用/过期/审核/成功等关键状态齐全。
- 导航、返回、关闭、取消、提交反馈全局一致。
- Com Design token / component / typography / spacing / radius / surface / hit target 收口。

**最终通过标准**：不是“约 150 页都画完”，而是**项目能跑、能点、能改；功能没丢、骨架正确、5 条母动线连续、状态可信、代码可维护、中保真视觉统一**。
