# 核心产业学院 App 重构评审卡

> **评审线程职责：每次评审先检查 `00-master-outline.md`，再检查对应任务卡。**
> 评审优先级固定为：**总纲一致性 > 母动线 > 功能覆盖 > 状态完整 > Com Design 视觉一致性**。
> 页面好看但走不通，直接不通过。

## R01 — T01 页面总图 / 动线评审

**必查总纲**：产品原则、5 条母动线、真相源优先级。

**检查**
- 旧功能是否全部有去向；删除/归档是否有理由。
- 一级导航是否服务“参赛 + 就业 / 实习”。
- 公共平台与赛事上下文是否分清。
- 5 条母动线是否都有入口、主动作、结果和返回路径。
- 是否提前暴露需要产品拍板的问题，而不是偷偷假设。

**拒绝条件**：页面树只是模块清单，没有真实 Flow；或靠新增功能填结构漏洞。

---

## R02 — T02 公共平台评审

**必查总纲**：A 新用户公共平台、B 三创赛参赛入口、D 就业 / 实习。

**检查**
- 首页第一屏能否快速理解“比赛 + 实习/就业”。
- 无赛事身份用户是否仍然是完整用户，不是残缺态。
- 赛事发现 -> 详情 -> 报名入口是否自然。
- 机会发现 -> 详情 -> 企业 -> 投递是否自然。
- 企业是否表达资源/品牌/机会关系，而非单纯招聘名录。
- 课程、权益、学习数据是否重新回到支撑层。

**拒绝条件**：需要用户频繁返回首页重新找入口；或一级入口名字与实际任务不一致。

---

## R03 — T03 三创赛 / 创赛工坊评审

**必查总纲**：B 三创赛参赛、C 赛事陪跑、E 赛后长期资产。

**检查**
- 报名响应式层与 App 原生层是否无双轨冲突。
- 报名成功/审核完成后是否明确获得赛事身份并进入正确赛事。
- 多赛事模型是否成立，没有把账号写死成三创赛用户。
- 工坊是否明确“当前赛事 / 当前项目 / 当前下一步”。
- S1–S6 是否无串线，每个任务都有完整回路。
- 无权限、审核中、结束、回收权限后的落点是否合理。

**拒绝条件**：工坊仍像功能宫格；或赛事结束后用户/资产一起“消失”。

---

## R04 — T04 长期资产 / 支撑系统评审

**必查总纲**：长期账号原则、企业原则、赛后长期资产动线。

**检查**
- 课程、权益、可信成果、企业资源是否都能解释“为什么此时给用户看”。
- 赛事结束后课程进度、成绩、证书、经历是否仍可访问。
- 权益资格/领取/兑换/核销/失效是否状态完整。
- 投递记录、赛事经历、学习成果是否能汇入长期简历/个人资产。
- 可信项目是否连接真实结果，而不是另起孤立系统。
- “任务专区”若业务仍未定义，是否保持未实现而非猜测。

**拒绝条件**：支撑模块再次反客为主，或同一资产在多个模块重复、互不相认。

---

## R05 — T05 全量终审

**必查总纲**：全文逐项检查，不接受抽样代替母动线回归。

**必须实走 5 条母动线**
1. 新用户公共平台。
2. 三创赛报名与身份获得。
3. 赛事陪跑与创赛工坊。
4. 就业 / 实习投递。
5. 赛后长期资产。

**全局检查**
- 旧 -> 新功能覆盖无无故缺口。
- 页面不存在明显死路、孤岛、错返回、串赛事上下文。
- 主按钮与下一步一致，不用用户猜。
- 空/错/禁用/过期/审核/成功等关键状态齐全。
- 导航、返回、关闭、取消、提交反馈全局一致。
- Com Design token / component / typography / spacing / radius / surface / hit target 收口。

**最终通过标准**：不是“约 150 页都画完”，而是**功能没丢、骨架正确、5 条母动线连续、状态可信、视觉统一**。
