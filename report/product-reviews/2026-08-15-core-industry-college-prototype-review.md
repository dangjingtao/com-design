# 核心产业学院 App 原型评审 — 2026-08-15

> 状态：Draft / 持续评审  
> 范围：本次 Mockplus 导出原型（140 个页面/状态）  
> 评审基线：产品信息架构、关键任务闭环、交互正确性、Com Design 一致性与研发落地风险。  
> 本文属于产品评审记录，不是 Com Design Core 真相源，不修改 `design-source/` 或 `design.md` 的规范语义。

---

## 1. 结论先行

这版原型已经不再只是“赛事报名 App”。它同时承载了：

- 赛事报名与团队管理；
- 课程、考试、证书与学力值；
- 企业、实训和岗位；
- 赛友内容；
- 可信数字教育身份/证书；
- 福利与兑换；
- AI 创赛工坊；
- 智能客服；
- 新增但尚未完成的任务专区。

**当前最大问题不是某个页面好不好看，而是两代产品模型叠在了一起：**

1. 旧模型：`赛事 + 学院 + 社区 + 我的`，核心是参赛与学习工具；
2. 新模型：`学力值 + 任务 + 权益/活动 + 可信资产 + AI 工坊 + 企业机会`，核心已经接近持续运营和成长平台。

首页已经明显进入第二种模型，但底部一级导航和大量二级页面仍然停留在第一种模型，因此用户会出现“看得到很多能力，但不知道这个 App 到底是干什么的”的认知断裂。

这不是视觉精修可以解决的问题。下一轮应该先收敛产品心智和一级信息架构，再做系统性 UI 收口。

## 2. P0：必须先修的交互/流程错误

### P0-1 报名答题链路跳进了课程成就模块

关键链路原本应为：

`赛事详情 -> 选择队长/队员 -> 基础信息 -> 报名答题 -> 注册成功 -> 团队信息/等待队长`

但当前“报名答题”页面的提交交互实际跳转到：

`可领取成就（课程详情）`

而不是“三创注册成功弹窗（队长/队员）”。

这会导致报名主流程直接串到课程系统。后续已经画好的“注册成功 -> 团队待审核 -> 审核通过 -> 承诺书”等页面也因此无法通过主链路正常进入。

**判断：高概率是复制页面后未重绑交互。**

研发前必须把报名状态机按角色重新走一遍，不要只按页面逐张验收。

### P0-2 创赛工坊存在大面积跨任务串线

工坊内部已经画出 S1/S2/S3/S4/S5/S6 多组动态答题、生成确认、任务进度和成果详情，但交互仍大量指向 S2 或 S5 的页面，例如：

- S3 动态答题 -> S2 生成确认；
- S3 生成确认 -> S2 动态答题；
- S1/S4/S6 的部分进度/成果 -> S2 成果；
- 多个不同阶段统一跳到 S5 任务进度。

这说明视觉模板已经复制出来，但**任务实例/步骤状态的交互语义没有真正拆开**。

如果研发照原型实现，会把“不同技能任务”误做成一套硬编码页面跳转。建议研发模型先统一成：

`TaskDefinition -> TaskRun -> Step -> Artifact`

页面只是状态投影，S1-S6 不应靠复制页面形成六套流程。

### P0-3 新增“任务专区”目前是空页面且首页无有效跳转

原型中已经新增一级页面“任务专区”，但页面本身没有组件；首页虽然已经出现“任务专区”入口文字，当前交互图中也没有连接到该页面。

与此同时，旧“创赛福利”下面已经存在“日常任务 / 核心任务”。

这会产生两个问题：

1. 产品语义重复：到底哪个才是统一任务中心；
2. 技术模型重复：学力值任务、活动任务、赛事任务是否属于同一个任务引擎尚未明确。

在这个问题确认之前，不建议继续画任务专区细节。

## 3. P1：产品结构问题

### P1-1 “创赛福利”仍然是旧的优惠券/兑换中心模型

当前页面核心内容是：

- 打车券；
- 外卖券；
- 限时学力值福利；
- 课程兑换；
- 招聘会入场券；
- 学力值兑换。

它仍然天然让人理解成“积分商城/福利中心”。如果产品接下来要承载更多线下活动、本地运营、学校/社团运营和营销权益，这个结构不足以支撑新的业务想象。

此前已经讨论过将这一块向更完整的运营品牌“创域”演进。**当前原型还没有完成从“福利货架”到“活动与权益运营场”的结构切换。**

下一版不应该只是把标题从“创赛福利”改成“创域”，而应重新定义其内容对象：

`活动 / 权益 / 名额 / 任务 / 核销 / 本地化 / 运营方`

否则只是换皮。

### P1-2 “社区”这个一级名称已经与真实内容不匹配

社区页实际承担的是：

- 官方/品牌资讯；
- 企业列表；
- 实训机会；
- 企业详情与岗位。

而“赛友风采”已经独立进入首页，产品又明确不准备做传统论坛。

因此现在“社区”会制造错误预期：用户以为会进入 UGC、讨论、动态流，实际进去却更像“资讯 + 企业 + 机会”。

这里需要重新确认一级心智，候选方向可能是“发现 / 机会 / 资源”等，但不建议现在直接定名，先确认这一栏最终承担什么用户任务。

### P1-3 新的多角色模型还没有体现在产品边界上

当前登录、资料填写和多数主链路仍默认“参赛学生”是中心角色。

如果账号未来允许学生之外的更多身份，并通过动态身份标签决定资源与权限，那么原型至少需要明确：

- 身份是完全无感的后台权限标签，还是用户可感知/可切换；
- 同一个入口是否因身份返回不同内容；
- 学校、社团、企业、运营人员的活动管理能力是否在同端出现；
- 哪些能力属于普通用户端，哪些属于运营工作台。

否则 IA 很容易按“所有角色都塞进一个 App”继续膨胀。

### P1-4 学力值已经成为平台货币，但经济闭环尚未说清

学力值目前同时出现在：首页、学院、我的、福利、兑换、任务等模块，实际上已经成为跨模块基础设施。

但用户尚不容易回答三件事：

1. 我为什么要赚学力值；
2. 我通过什么稳定行为赚；
3. 最有价值的东西能用学力值换什么。

如果任务专区继续推进，建议把“行为 -> 学力值 -> 权益/成长资产”设计成一个统一闭环，而不是每个模块各自放一个余额数字。

### P1-5 创赛工坊的能力很强，但首页仍缺一个明确的主动作

工坊已经包含算力、技能推荐、运行中任务、成果、技能矩阵、项目阶段等概念，信息量很大。

问题是用户进入后不容易第一眼知道“我现在最该做什么”。

下一轮应该优先建立一个明确的当前阶段主任务，例如：

`继续当前任务 / 开始下一项诊断 / 查看待确认成果`

然后再展示算力与技能矩阵。否则它容易像 AI 能力仪表盘，而不是一个帮助团队推进比赛的工作台。

## 4. P2：Com Design 一致性问题

这部分可以后处理，不建议抢在 P0/P1 前面做大面积精修。

### 4.1 字体与字号过度自由

原型中主要混用了 Microsoft YaHei 与 PingFang SC，且存在大量非 Com Design 语义字号。

抽样统计全原型：

- `8px`：约 65 处；
- `10px`：约 441 处；
- `15px`：约 135 处；
- `17px`：约 96 处；
- 另有 `26 / 36 / 48` 等业务页面直接字号。

Com Design 已定义 `12 / 14 / 16 / 18 / 24 / 28` 为主要语义层级。下一轮 UI 收口应从“逐个改字号”升级为“文本角色映射”。

尤其 `8px / 10px` 的正文和辅助信息，在真实移动设备上可读性风险很高。

### 4.2 阴影使用显著超出 Flat-first 原则

原型中检测到约 470 个启用阴影的节点，大量普通卡片依赖阴影形成边界。

Com Design 的规则是普通 Card / Button / List Item 不应默认使用装饰阴影；层级优先通过间距、surface、border、typography 建立。

建议后续统一清理，而不是每张页面人工“淡一点”。

### 4.3 交互热区需要实现侧兜底

原型中存在大量视觉节点小于 44×44 的交互对象，例如 16px 返回图标、18px 筛选图标、24px 行项目等。

其中一部分可能由父容器扩大了真实点击区域，但原型数据本身无法保证。

研发验收必须落实：

- iOS 默认向 44×44pt 交互区域靠拢；
- Android 至少 48×48dp；
- 小图标可以视觉小，但 hitSlop / 父容器不可小。

### 4.4 Radius 和组件外观仍有较多一次性值

原型中除 4/8/12/16 外还出现 2/3/5/11/19/20/24 等多种圆角值。

后续需要统一映射回 Com Design 的语义 radius，不继续按页面视觉手调。

## 5. 内容与可信性问题

### 5.1 仍有较多占位内容

当前至少 24 个页面包含 `xxx / 2026-xx-xx / XXXXXXXXX` 等明显占位内容。

这本身不是原型错误，但已经开始影响交互判断。例如赛事截止日期、企业地址、课程人数、赛事简介等都决定用户是否采取下一步行动。

下一轮在关键路径上应优先替换真实级别样例，而不是继续补视觉。

### 5.2 岗位详情存在明显无关占位文案

“岗位详情”的实训描述目前使用“酒与污水定律”文本，与岗位内容完全无关。

这类占位会掩盖真正的内容结构问题：岗位职责、要求、周期、地点、补贴/薪资、企业、截止时间、投递条件等字段到底需要哪些。

### 5.3 可信空间包含需要业务/法务确认的强声明

例如“与纸质盖章证书同等法律效力”属于高强度可信声明。

设计层面不判断其法律事实，但上线前必须明确：

- 对应哪一类电子凭证；
- 授权来源和适用范围；
- 是否所有平台/证书都满足；
- 页面需要展示何种来源、说明或免责声明。

不要让营销式强文案跑在实际授权边界前面。

## 6. 当前建议的评审顺序

下一轮不要按“140 张页面逐张修”推进，建议按下面顺序：

1. **先定产品心智与一级 IA**：这到底是赛事工具，还是围绕学生/青年成长的持续运营平台；
2. **定义统一对象模型**：身份、赛事、项目、任务、活动、权益、学力值、资产；
3. **修 P0 状态机**：报名、工坊任务两条链路先跑通；
4. **确定任务专区与创域的边界**；
5. **再做 Com Design 视觉收口**；
6. **最后补齐异常态、权限态、空态和真实数据样例。**

---

## 7. 暂不建议现在做的事

- 不建议先把 140 页全部换成统一配色；
- 不建议先继续扩更多首页金刚区入口；
- 不建议为“创域”只换名称不改内容模型；
- 不建议把学校/社团/企业后台能力全部直接塞进普通用户端；
- 不建议继续复制 S1-S6 页面来表达任务差异；
- 不建议让“学力值”在每个模块各自长一套规则。
